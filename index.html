HTML Analog Clock Benchmark

One-shot prompt: build an analog clock as a single HTML file. Scored on time accuracy, visuals, dial completeness, code quality, and smoothness.

The task is simple but revealing: give a frontier LLM a one-shot prompt to build an analog clock in a single HTML file and see what it produces. The prompt makes no special concessions for any model — it expects the model to infer everything about clock geometry from the request alone.

The rubric scores five dimensions: Time Accuracy (×3 weighting) — do hands point to the correct positions using correct math? Visuals (×2) — does it look like a real clock? Markers & Numbers (×1.5) — dial completeness and placement. Code Quality (×1.5) — clean architecture, no leaky globals. Smoothness (×1) — smooth sweep vs. snapping tick.

Generate a single HTML file that displays a working analog clock showing the current time with hour, minute, and second hands.
TypeSafe Jev acted as judge — one typed yes/no question per rubric criterion over each clock's source, scored by rejudge_index.py on 2026-09-26. A render check then opens each clock in headless Chromium with the time frozen and measures where the hands actually point; when that is conclusive it decides whether the clock shows the right time, overriding the judge (source-reading missed three clocks whose hands were rotated). Each card's Earned/Lost summary is generated from its Jev audit (audits.json), so it always matches the score; the original hand review, where one exists, sits under “Original review” and may describe an earlier score. See docs/rejudge-2026-09-26.md for the per-dimension before and after.
