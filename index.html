HTML Analog Clock Benchmark

One-shot prompt: build an analog clock as a single HTML file. Scored on time accuracy, visuals, dial completeness, code quality, and smoothness.

About this benchmark

The task is simple but revealing: give a frontier LLM a one-shot prompt to build an analog clock in a single HTML file and see what it produces. The prompt makes no special concessions for any model — it expects the model to infer everything about clock geometry from the request alone.

The rubric scores five dimensions: Time Accuracy (×3 weighting) — do hands point to the correct positions using correct math? Visuals (×2) — does it look like a real clock? Markers & Numbers (×1.5) — dial completeness and placement. Code Quality (×1.5) — clean architecture, no leaky globals. Smoothness (×1) — smooth sweep vs. snapping tick.

Generate a single HTML file that displays a working analog clock showing the current time with hour, minute, and second hands.
Opus 4.7 acted as judge — scoring all model outputs across every dimension.

Only SVG entry. viewBox="-120 -120 240 240" puts the origin at the clock center — off-by-eight bugs are not even possible. ms precision, 50 ms refresh. Minimal but tasteful styling.
Opus 4.7 #3 · 9.3
Most polished CSS clock. Numbers, 60 ticks (12 major), correct pivot pattern, 50 ms refresh, ms-precision second hand. Tick transform-origin computed exactly to land at the rim.
Kimi K2.5 #4 · 9.0
Feature-rich, source-bloated. Numerals, 60 ticks, gradient hands, glowing center, embedded digital readout. Correct everything, but ticks are 60 hand-written divs.
Sonnet 4.6 #5 · 8.9
Cleanest correct code. Canvas, ms-precision, three hands with small tails, quarter-hour markers thicker, 48 minute markers, layered center dot. No numerals — only markers.
Kimi K2.6 #6 · 8.8
Cleaner K2.5 with a regression. Same red-bezel look. Ticks refactored into a loop. Correct math, correct pivots — but 1 Hz setInterval so the second hand snaps.
Gemini 3.1 Pro #7 · 8.1
Classic JS30 look. Clean white face, twelve numerals, three hands with a tasteful overshoot-bounce on each second. Includes snap-glitch hack for minute rollover. No tick marks; 1 Hz refresh.
ChatGPT Free #8 · 7.6
Correct but jumpy. Numbers, 60 ticks, three hands, properly centered pivots. Flaw: setInterval(…, 1000) with no millisecond term — the second hand jumps a full step each tick.
MiMo 2.5 Pro #9 · 7.5
Off-by-eight dial. Glowing red bezel, full numerals, 60 ticks, ms-precision math, rAF loop. But box-sizing: border-box mismatch puts the tick ring and number ring on different centers than the hands.
Qwen 3.6 Plus #10 · 7.1
Same border-box bug, jumpier seconds. Same hard-coded-center bug as mimo but with a 1 Hz setInterval second hand that snaps each tick.
Grok 4.2 Expert #11 · 6.9
Breaks out of its container. 420 px container holds a width: 100% clock with 48 px border and no box-sizing: border-box — bezel spills past the layout frame. Hand pivots 2–6 px below center; second hand pulses opacity.
MiniMax M2.7 #12 · 6.6
Compound centering bug. margin-left: -halfWidth in CSS and translateX(-50%) in JS both apply — compounding the pivot offset. No minute markers or numerals; 1 Hz refresh.
