Cloud LLM Clock Benchmark — 12 Models

Twelve frontier-class cloud models, same one-shot prompt: build an analog clock as a single HTML file. Live render of each, scored on time accuracy, visuals, dial completeness, code quality, and smoothness. (Strongest local model on this prompt — qwen2.5-coder-14b — scored 7.8 on the same rubric and would land between #7 and #8 here.)

glm-5.1.html #1 · 9.5
Cloud winner. Canvas with cream radial-gradient face, serif numerals 1–12, 12 hour and 48 minute markers, triangular polygon hour/minute hands, thin red second hand with counterweight. requestAnimationFrame loop. Real-watch aesthetic.
deepseek-v4-pro.html #2 · 9.4
Only SVG entry. viewBox="-120 -120 240 240" puts the origin at the clock center, so every element shares one coordinate frame — off-by-eight bugs are not even possible. Minimal but tasteful styling: red bezel, dark face, red/white/yellow hands. ms precision, 50 ms refresh.
opus 4.7.html #3 · 9.3
Most polished CSS clock. Numbers, 60 ticks (12 major), correct pivot pattern (no double-centering bug), 50 ms refresh, ms-precision second hand. Tick transform-origin: 50% 176px computed exactly to land at the rim.
kimi k2.5.html #4 · 9.0
Feature-rich, source-bloated. Numerals, 60 ticks, gradient hands, glowing center, embedded digital readout. Correct everything, but ticks are hand-written as 60 individual divs and the second hand has a slight overshoot bounce.
sonnet 4.6.html #5 · 8.9
Cleanest correct code. Canvas, ms-precision, three hands with small tails, quarter-hour markers thicker, 48 minute markers, layered center dot. No numerals — only markers — so visually leaner than the top three.
kimi k2.6.html #6 · 8.8
Cleaner k2.5 with a smoothness regression. Same red-bezel / dark-face look. Refactored 60 ticks into a loop, dropped the digital readout. Correct math, correct pivots — but 1 Hz setInterval and no ms term, so the second hand snaps each tick instead of sweeping.
gemini-3.1-pro.html #7 · 8.1
Classic JS30 look. Clean white face, thick light bezel, twelve numerals, three hands with a tasteful overshoot-bounce on each second. Includes the snap-glitch hack so hands don't unwind 360° at minute rollover. No tick marks; 1 Hz refresh.
chatgpt-free.html #8 · 7.6
Correct but jumpy. Numbers, 60 ticks, three hands, correct math, properly centered pivots. Only flaw: setInterval(…, 1000) with no millisecond term so the second hand jumps a full step each tick.
mimo-2.5-pro.html #9 · 7.5
Off-by-eight dial. Glowing red bezel, full numerals, 60 ticks, ms-precision math, rAF loop. But box-sizing: border-box makes the inner face 304 px while the JS lays out ticks and numbers as if it were 320 px. Hands rotate around true center; tick ring sits ~8 px low; number ring ~8 px down-right. Three different centers in one clock.
qwen-3.6-plus.html #10 · 7.1
Same border-box bug, jumpier seconds. Clean classic look, correct hand pivot — but identical hard-coded-center bug to mimo: face is 284 px not 300 px, so ticks orbit ~8 px below center and numbers ~8 px down-right. Worse, the second hand is s * 6 on a 1 Hz setInterval, so it snaps each tick.
grok 4.2 expert.html #11 · 6.9
Breaks out of its container. 420 px clock-container holds a width: 100% clock with 48 px of border and no box-sizing: border-box — total visible 468 px, so the bezel spills past the layout frame on every side. On top of that: hand pivots are 2–6 px below the geometric center, and the second hand pulses opacity — a clock should not fade. (Revised from 7.6 after re-checking the rendered output.)
minimax-m2.7.html #12 · 6.6
Compound centering bug. Hands have margin-left: -halfWidth in CSS *and* translateX(-50%) in the JS rotate — both shift left, so pivots end up halfWidth left of true center. No minute markers or numerals; 1 Hz refresh.
